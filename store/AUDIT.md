# Store audit: Transport (iPhone and Android)

Checked on 24 October 2026 against the App Store Review Guidelines, Apple's privacy manifest and required reason API
rules, and Google Play's developer policies (User Data, Permissions, Target API level, Data safety). App type: transit
information from Transport for NSW open data, no login, optional location.

## Blockers found and fixed

| # | Blocker | Rule | Fix |
| --- | --- | --- | --- |
| 1 | Every install used the same server profile ("bidur"), so every user would see and change Bidur's saved trips, commutes and home trip, and Ask's "last train home" would use his home | Apple 5.1.1 and 5.1.2 (data privacy), 2.1 (completeness); Play User Data | Each install now makes its own random profile on first launch (iPhone: AppIdentity in TransportKit; Android: initProfile in src/lib/device.ts). Existing Android installs keep the old profile. The iPhone and Android widgets read the same profile (app group on iPhone, the app's key value store on Android) |
| 2 | No privacy manifest; the app and widget read UserDefaults, a required reason API | Apple privacy manifest requirement (ITMS-91053 on upload) | ios-native/Support/Privacy/App and Widget PrivacyInfo.xcprivacy: no tracking, collected types DeviceID, SearchHistory, OtherUserContent (not linked, app functionality), UserDefaults reasons CA92.1 and 1C8F.1 |
| 3 | Widget had no shared container with the app | Needed for 1 | App group group.com.maisysen.nswtransport on the app and widget (entitlements generated by project.yml) |
| 4 | Bundle ID was in the builder's namespace, not Bidur's | Must be registered on his team | com.maisysen.nswtransport, widget .widget, matching the Android application ID. Background task ID and URL type renamed with it |
| 5 | Location usage text "Shows the stops closest to you." did not cover planning from your location or Siri | Apple 5.1.1(ii) purpose strings | "Transport uses your location to show the stops and stations closest to you and to plan trips from where you are." |
| 6 | No data attribution, endorsement disclaimer, privacy policy or support link inside the apps | CC BY 4.0 terms; Apple 5.1.1(i); Play User Data (in app privacy link) | iPhone Settings and Android Settings: attribution footer, independence statement, Help and support, Privacy policy |
| 7 | Privacy policy did not match what the server keeps (no retention periods, no mention of Ask, Siri location, map tiles) and retention was not enforced | Apple 5.1.1(i), Play User Data | Policy rewritten and republished; the server now deletes trip searches after 90 days and finished watches after 30 days |
| 8 | Support URL was the APK download page (a sideload page) | Apple 1.5 (support URL), 2.3 | New page https://transportsydney.app/support/ with help, deletion and contact |

## Checked and already fine

* Export compliance: ITSAppUsesNonExemptEncryption is false (HTTPS only, exempt).
* App icon: 1024 x 1024, RGB with no alpha, single size asset catalog (Xcode builds every size). Android adaptive icon with monochrome layer.
* Launch screen: UILaunchScreen (system background, light and dark). Android splash light and dark.
* Device family: iPhone only (TARGETED_DEVICE_FAMILY 1, UIRequiresFullScreen), so no iPad screenshots. Runs in compatibility mode on iPad.
* Minimum OS: iOS 17.0 (needed for interactive widgets and App Intents); Android 7.0 (API 24). Android targetSdk 36, compileSdk 37.
* Location is asked only on a user action (Show stops near me), foreground only. No background location on either platform.
* Notifications: iPhone uses local notifications; asked only when you watch a trip or tap Allow notifications.
* No login, no accounts, so account deletion rules (5.1.1(v)) do not apply.
* Dark mode: every screen is captured in dark by CI. Dynamic Type works through system text styles.
* Accessibility: icon only buttons have labels (Send in Ask, swipe actions have text, tab items have titles). Countdown chips read as text.
* No placeholder, lorem, beta or test strings in the UI. Test hooks (-screen, -uiTestReset, -apiBase) are launch arguments only; -apiBase is compiled into Debug builds only.
* Siri: App Shortcuts include the app name in each phrase, as Apple requires ("Next train home in Transport", "Ask Transport").
* Third party content: TfNSW data is CC BY 4.0; maps are Apple Maps on iPhone and OpenStreetMap data via OpenFreeMap on Android, both credited.
* No secrets in the app or repo: the TfNSW key stays on the server.

## Left, and why

* Anything that needs the developer accounts: registering IDs, the app records, signing, uploads, the listing forms. See SUBMIT.md.
* The name "Transport: Sydney Live" can only be confirmed as free when the App Store Connect record is created.
* Play phone screenshots are rendered from the same React Native code in a phone sized browser (1080 x 1920), not captured on an Android device: this box has no hardware acceleration for an emulator and the online device minutes are used up. They show the real screens with live data; swap in device captures from the first internal test build if wanted.
* The web app (not in either store) still uses the shared profile by default. Worth the same per install fix later.
* New Google personal developer accounts need a 14 day closed test with 12 testers before production.
